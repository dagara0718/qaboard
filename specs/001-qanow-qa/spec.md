# Feature Specification: QANOW 질의응답 게시판

**Feature Branch**: `001-qanow-qa`

**Created**: 2026-08-20

**Status**: Draft

**Input**: QANOW 회원 질문 관리자 답변 게시판. 목표: 사용자 질문 작성, 질문/답변 상태 조회, 관리자 답변 관리, 메인 페이지 이해 용이. 핵심 화면 3개(메인, 리스트, 상세). 사용자 3종(비회원, 회원, 관리자). 회원 기능 7개, 관리자 기능 5개. 권한 규칙 4개. 입력 규칙 3개. 상태 5가지. MVP 제외 6개.

## Overview

QANOW는 회원이 질문을 등록하고 관리자가 답변하는 Q&A 게시판입니다. 비회원도 메인 페이지에서 서비스를 이해할 수 있으며, 회원가입 후 질문을 작성하고 답변을 확인할 수 있습니다. 관리자는 미답변 질문을 찾아 체계적으로 답변합니다.

## User Scenarios & Testing

### User Story 1 - 메인 페이지 서비스 이해 (Priority: P1)

비회원이 메인 페이지를 방문했을 때 QANOW 서비스의 목적과 사용 흐름(질문 작성 → 관리자 확인 → 답변 확인)을 명확하게 이해할 수 있어야 합니다.

**Why this priority**: 비회원을 회원으로 전환하기 위한 첫 번째 진입점입니다. 메인 페이지가 명확하지 않으면 회원가입 의지가 저하됩니다.

**Independent Test**: 메인 페이지에서 서비스 소개, 이용 흐름 다이어그램, 회원가입 CTA를 확인하는 것만으로 기능을 검증할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 비회원이 메인 페이지에 접속, **When** 페이지를 로드, **Then** 서비스 소개 텍스트와 이용 흐름(3단계)이 시각적으로 표시됨
2. **Given** 비회원이 메인 페이지를 봤을 때, **When** 회원가입 버튼 클릭, **Then** 회원가입 페이지로 이동
3. **Given** 이미 회원인 경우, **When** 메인 페이지에서 로그인 상태 확인, **Then** 로그인 상태를 표시하고 "내 질문 보기" CTA를 표시

---

### User Story 2 - 회원가입 및 로그인 (Priority: P1)

비회원이 회원가입하고 로그인하여 질문 작성 기능에 접근할 수 있어야 합니다.

**Why this priority**: 모든 주요 기능의 선행 조건입니다. 회원가입과 로그인이 없으면 질문 작성이 불가능합니다.

**Independent Test**: 새 사용자로 회원가입 완료 → 로그인 → 보호된 페이지(예: 질문 작성) 접근 가능 여부로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 회원가입 페이지가 로드됨, **When** 이메일과 비밀번호 입력 후 회원가입 버튼 클릭, **Then** 계정이 생성되고 로그인 페이지로 리다이렉트
2. **Given** 회원가입 완료, **When** 이메일과 비밀번호로 로그인, **Then** 로그인 성공하고 질문 리스트 페이지로 리다이렉트
3. **Given** 로그인 상태의 회원, **When** 메인 페이지 방문, **Then** 로그아웃 버튼과 "내 질문 보기" 메뉴가 표시됨

---

### User Story 3 - 회원의 질문 작성 (Priority: P1)

회원이 질문을 작성하여 관리자에게 전달할 수 있어야 합니다.

**Why this priority**: 서비스의 핵심 가치 제공 기능입니다. 질문이 없으면 게시판이 성립하지 않습니다.

**Independent Test**: 로그인한 회원이 질문 작성 폼을 채우고 제출 → 질문 리스트에 표시되는 것으로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 로그인 상태의 회원이 질문 리스트 페이지에 있음, **When** "질문 작성" 버튼 클릭, **Then** 질문 작성 폼(제목, 내용)이 표시됨 (같은 폼을 작성/수정 모드로 재사용)
2. **Given** 질문 작성 폼이 열림, **When** 제목(50자)과 내용(500자) 입력 후 "작성" 버튼 클릭, **Then** 질문이 저장되고 "답변 대기" 상태로 표시
3. **Given** 질문 작성 중, **When** 필수 필드 없이 "작성" 버튼 클릭, **Then** 경고 메시지가 표시되고 저장 방지

---

### User Story 4 - 회원의 질문 목록 조회 (Priority: P1)

회원이 자신이 작성한 질문의 목록을 보고, 각 질문의 답변 상태(대기 중/답변됨)를 확인할 수 있어야 합니다.

**Why this priority**: 회원이 답변을 받았는지 확인하는 핵심 기능입니다.

**Independent Test**: 로그인한 회원이 질문 리스트 페이지 → 자신의 질문만 필터링되어 표시되는 것으로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 질문 리스트 페이지에 접속, **When** 페이지 로드, **Then** 자신이 작성한 질문 목록이 시간 역순으로 표시 (필터링 UI 없음)
2. **Given** 질문 목록이 표시됨, **When** 각 질문 항목 확인, **Then** 제목, 작성일, 답변 상태(대기 중/답변됨) 배지가 표시
3. **Given** 작성한 질문이 없을 때, **When** 질문 리스트 페이지 접속, **Then** "작성한 질문이 없습니다"라는 메시지만 표시 (CTA 버튼 없음)

---

### User Story 5 - 회원의 질문 상세 조회 및 관리자 답변 확인 (Priority: P1)

회원이 자신의 질문 상세 내용과 관리자의 답변(있을 경우)을 확인할 수 있어야 합니다.

**Why this priority**: 질문에 대한 답변을 확인하는 최종 목표입니다.

**Independent Test**: 질문 리스트에서 항목 클릭 → 상세 페이지에서 질문 내용과 답변(있을 경우) 확인으로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 질문 리스트에서 질문 항목이 표시됨, **When** 항목 클릭, **Then** 질문 상세 페이지로 이동하여 제목, 내용, 작성일이 표시
2. **Given** 답변 대기 중인 질문 상세 페이지, **When** 페이지 로드, **Then** "답변 대기 중" 상태와 수정/삭제 버튼이 표시
3. **Given** 관리자가 답변한 질문 상세 페이지, **When** 페이지 로드, **Then** 질문 내용 아래에 답변 내용이 표시되고 수정/삭제 버튼 비활성화

---

### User Story 6 - 회원의 질문 수정/삭제 (답변 전) (Priority: P2)

회원이 관리자의 답변을 받기 전에 자신의 질문을 수정하거나 삭제할 수 있어야 합니다.

**Why this priority**: 질문 작성 후 오류 수정이 필요할 수 있으며, 이는 사용자 경험을 향상시킵니다.

**Independent Test**: 답변 대기 중인 질문에서 수정 버튼 클릭 → 수정 가능 확인으로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 답변 대기 중인 질문 상세 페이지, **When** "수정" 버튼 클릭, **Then** 질문 수정 폼이 열리고 기존 내용이 표시됨 (작성과 같은 폼, 수정 모드)
2. **Given** 질문 수정 폼이 열림, **When** 내용 수정 후 "저장" 버튼 클릭, **Then** 질문이 업데이트되고 상세 페이지로 돌아감
3. **Given** 답변 대기 중인 질문 상세 페이지, **When** "삭제" 버튼 클릭, **Then** 확인 대화상자가 표시되고 확인 후 질문이 삭제됨

---

### User Story 7 - 관리자의 미답변 질문 확인 및 답변 작성 (Priority: P1)

관리자가 로그인하여 모든 질문의 목록을 보고, 미답변 질문을 찾아 답변할 수 있어야 합니다.

**Why this priority**: 관리자 역할의 핵심 기능입니다. 답변이 없으면 게시판의 가치가 없습니다.

**Independent Test**: 관리자 로그인 → 전체 질문 목록 확인 → 답변 작성 완료로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 관리자 로그인, **When** 질문 리스트 페이지 접속, **Then** 모든 사용자의 질문이 시간 역순으로 표시되고 답변 상태 배지가 표시됨 (필터링 UI 없음, 배지로만 구분)
2. **Given** 전체 질문 목록이 표시됨, **When** 미답변 질문 항목 확인, **Then** "답변 대기" 배지와 함께 작성자 이름도 함께 표시
3. **Given** 미답변 질문의 상세 페이지, **When** "답변 작성" 버튼 클릭, **Then** 답변 입력 폼(텍스트 에어리어)이 표시
4. **Given** 답변 입력 폼이 열림, **When** 답변 내용(1-5000자) 입력 후 "저장" 버튼 클릭, **Then** 답변이 저장되고 상태가 "답변됨"으로 변경

---

### User Story 8 - 관리자의 답변 수정 (Priority: P2)

관리자가 자신이 작성한 답변을 수정할 수 있어야 합니다.

**Why this priority**: 답변 작성 후 오류 수정이 필요할 수 있으며, 품질 관리를 위해 중요합니다.

**Independent Test**: 답변된 질문에서 관리자 권한으로 수정 버튼 클릭 → 수정 가능 확인으로 검증됩니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 이미 답변한 질문 상세 페이지, **When** "답변 수정" 버튼 클릭, **Then** 기존 답변 내용이 입력 폼에 표시
2. **Given** 답변 수정 폼이 열림, **When** 답변 내용 수정 후 "저장" 버튼 클릭, **Then** 답변이 업데이트되고 상세 페이지로 돌아감

---

### Edge Cases

- 비회원이 보호된 화면(질문 작성, 내 질문 보기 등)에 접근하면 로그인 페이지로 리다이렉트
- 회원이 다른 회원의 질문을 수정/삭제하려고 시도하면 Toast 메시지로 "권한이 없습니다" 표시
- 관리자가 답변한 후 회원이 질문을 수정/삭제하려고 하면 Toast 메시지로 "이미 답변된 질문은 수정할 수 없습니다" 표시
- 입력 필드가 공백만 입력된 경우 유효하지 않은 입력으로 처리
- 네트워크 오류로 저장 실패 시 "저장 중" 상태 표시 후 재시도 옵션 제공
- 빈 목록일 때 메시지만 표시 (예: "작성한 질문이 없습니다"), CTA 버튼 없음
- 로딩 중일 때 스켈레톤 UI 또는 로딩 스피너 표시

## Requirements

### Functional Requirements

**Account & Authentication**

- **FR-001**: 시스템은 이메일과 비밀번호로 회원가입을 지원해야 함 (이메일 중복 검사 포함)
- **FR-002**: 시스템은 가입한 계정으로 로그인 및 로그아웃을 지원해야 함
- **FR-003**: 시스템은 비회원의 보호된 페이지(질문 작성, 내 질문 등) 접근 시 로그인 페이지로 리다이렉트해야 함
- **FR-004**: 시스템은 로그인 상태를 세션 또는 토큰으로 서버에서 관리해야 함

**Question Management (회원)**

- **FR-005**: 로그인 회원은 제목(1-100자, 공백 제거 후)과 내용(1-5000자, 공백 제거 후)으로 질문을 작성할 수 있어야 함
- **FR-006**: 시스템은 질문 작성 시 입력 유효성(길이, null 체크)을 서버에서 검증해야 함
- **FR-007**: 시스템은 회원의 질문 목록을 자신이 작성한 것만 필터링하여 표시해야 함 (시간 역순)
- **FR-008**: 시스템은 각 질문의 답변 상태(대기 중/답변됨)를 명확히 표시해야 함
- **FR-009**: 답변 대기 중인 질문에 한해 회원은 수정할 수 있어야 함
- **FR-010**: 답변 대기 중인 질문에 한해 회원은 삭제할 수 있어야 함
- **FR-011**: 답변이 작성된 후에는 해당 질문을 수정/삭제할 수 없어야 함 (UI & DB 계층 모두)
- **FR-012**: 회원은 다른 회원의 질문을 수정/삭제할 수 없어야 함 (서버 권한 검증)

**Answer Management (관리자)**

- **FR-013**: 로그인 관리자는 모든 질문의 목록을 볼 수 있어야 함 (시간 역순, 사용자별 구분 표시)
- **FR-014**: 시스템은 질문별 답변 상태(대기 중/답변됨)를 표시해야 함
- **FR-015**: 관리자는 미답변 질문에 대해 답변(1-5000자, 공백 제거 후)을 작성할 수 있어야 함
- **FR-016**: 시스템은 답변 작성 시 입력 유효성(길이, null 체크)을 서버에서 검증해야 함
- **FR-017**: 관리자는 자신이 작성한 답변을 수정할 수 있어야 함
- **FR-018**: 다른 관리자가 작성한 답변을 수정할 수 없어야 함 (권한 검증)

**Permission & Authorization**

- **FR-019**: 시스템은 모든 데이터 변경(질문 작성/수정/삭제, 답변 작성/수정)을 서버/DB 계층에서 권한으로 검증해야 함
- **FR-020**: 시스템은 클라이언트로부터 받은 권한 정보를 신뢰하지 않고 서버 세션에서 재확인해야 함
- **FR-021**: 회원의 질문 조회 쿼리는 자동으로 WHERE 절(본인 작성 질문만)이 적용되어야 함
- **FR-022**: 비로그인 사용자가 보호된 API 호출 시 401(Unauthorized) 또는 로그인 안내를 반환해야 함

**UI/State Management**

- **FR-023**: 시스템은 다음 상태를 UI에 명확하게 표시해야 함: 로딩, 빈 목록, 오류, 권한 없음, 저장 중
- **FR-024**: 로딩 중일 때 사용자는 상호작용 불가능하게 해야 함 (로딩 스피너 또는 스켈레톤 UI)
- **FR-025**: 저장 실패 시 오류 메시지와 재시도 옵션을 제공해야 함
- **FR-026**: 권한 없을 때 Toast 메시지로 명확한 오류(예: "권한이 없습니다")를 표시해야 함

**Main Page**

- **FR-027**: 메인 페이지는 서비스 소개와 이용 흐름(3단계: 질문 작성 → 관리자 확인 → 답변 확인)을 시각적으로 표시해야 함
- **FR-028**: 메인 페이지에는 회원가입 CTA 버튼이 있어야 함
- **FR-029**: 로그인 상태 회원이 메인 페이지 방문 시 "내 질문 보기" 메뉴가 표시되어야 함

**Responsive Design**

- **FR-030**: 모든 핵심 기능(질문 작성, 조회, 답변 작성)은 데스크톱과 모바일에서 완료 가능해야 함
- **FR-031**: 모바일 환경에서 터치 대상(버튼, 링크)은 최소 44×44px 이상이어야 함
- **FR-032**: 모바일 네비게이션은 상단 헤더(로그인/로그아웃, 로고) + 햄버거 메뉴(내 질문, 질문 작성, 계정 등)로 구성

### Key Entities

- **User**: id, email, password_hash, role(member/admin), created_at
- **Question**: id, user_id(작성자), title, content, created_at, updated_at, status(pending/answered)
- **Answer**: id, question_id, admin_id(작성자), content, created_at, updated_at

## Success Criteria

### Measurable Outcomes

- **SC-001**: 비회원이 메인 페이지에서 서비스의 목적과 이용 흐름을 1분 내에 이해 가능 (유저 테스트 기준: 3명 중 2명 이상 이해)
- **SC-002**: 회원이 가입부터 질문 작성까지 완료하는 데 소요되는 시간이 3분 이내 (측정: 신규 회원 5명의 평균 시간)
- **SC-003**: 관리자가 미답변 질문을 찾아 답변 작성까지 완료하는 데 소요되는 시간이 2분 이내 (측정: 관리자 3명의 평균 시간)
- **SC-004**: 모든 핵심 사용자 시나리오(가입, 질문 작성/조회, 답변 작성/확인)를 데스크톱과 모바일에서 완료 가능
- **SC-005**: 권한 없는 사용자가 다른 사용자의 질문을 수정/삭제할 수 없음 (100% 차단 검증)
- **SC-006**: 답변된 질문은 회원이 수정/삭제할 수 없음 (UI & API 계층 모두 차단)
- **SC-007**: 모든 입력 필드의 유효성 검증이 서버에서 수행됨 (클라이언트 우회 불가)
- **SC-008**: 메인 페이지 로딩 성능이 3G 네트워크에서 3초 이내 (First Contentful Paint 기준)
- **SC-009**: 모든 텍스트의 색상 대비율이 WCAG AA 기준 이상 (4.5:1 이상)
- **SC-010**: 모든 UI 상태(로딩, 빈 목록, 오류, 권한 없음, 저장 중)가 명확하게 구분 가능

## Assumptions

- 회원가입 시 이메일 인증은 MVP에서 제외하고, 이메일 중복 체크만 수행
- 비밀번호는 서버에서 bcrypt 또는 유사한 해싱 알고리즘으로 암호화하여 저장
- 세션 관리는 HTTP-only 쿠키 또는 서버 토큰 방식 (클라이언트의 로컬 스토리지는 사용 금지)
- 데스크톱 기준 뷰포트 1200px 이상, 모바일 기준 375px 이상 지원
- 모든 시간 데이터는 UTC 기준이며, 클라이언트에서 로컬 타임존으로 표시
- 삭제된 질문과 답변은 소프트 삭제 또는 하드 삭제 (명세에 따라 결정)
- 동시성 제어: 동일 질문을 여러 관리자가 동시에 답변할 경우 먼저 저장한 것이 우선 (낙관적 잠금)
- 에러 로깅은 서버에서 수행되며, 클라이언트에는 민감 정보(스택 트레이스, DB 스키마) 노출 금지
- Constitution의 13개 원칙 준수 (특히 권한 분리, 입력 검증, 명세 준수, 3화면 일관성, 접근성)

## Out of Scope (MVP 제외)

- 파일 첨부 (이미지, 문서 등)
- 댓글 기능
- 검색 기능
- 페이지네이션 (초기 버전은 모든 항목 로드)
- 소셜 로그인 (Google, GitHub 등)
- 통계 대시보드 (조회 수, 답변율 등)
