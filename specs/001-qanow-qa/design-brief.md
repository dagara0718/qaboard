# QANOW 설계 지시서 (Design Brief)

**Date**: 2026-08-20  
**Project**: QANOW 질의응답 게시판  
**Status**: Ready for Claude Design

---

## 1. 프로젝트와 사용자 요약

QANOW는 신뢰감 있는 Q&A 게시판 서비스입니다. 회원이 질문을 작성하면 관리자가 답변하는 구조로, 비회원도 메인 페이지에서 서비스를 이해하고 회원가입할 수 있습니다.

**사용자 3종류**:

- **비회원**: 메인 페이지에서 서비스 이해 후 회원가입 또는 로그인
- **회원**: 질문 작성 → 답변 확인, 자신의 질문만 관리
- **관리자**: 모든 질문 조회 → 미답변 질문 답변 → 답변 수정

**핵심 가치**:

- 빠르고 명확한 질의응답
- 답변 상태 추적 용이
- 관리자의 체계적인 질문 관리

---

## 2. 디자인 목표

1. **메인 페이지**: 강한 첫인상으로 서비스 목적을 1분 내 이해시킴
2. **내부 화면**: 가독성과 작업 효율을 최우선 (질문 작성, 조회, 답변 모두 3분 이내)
3. **신뢰감**: 금융/B2B 수준의 신뢰감 있는 톤
4. **모던함**: 과도하지 않은 미니멀한 모던 디자인
5. **접근성**: 색맹, 화면낭독기, 키보드만 사용 가능, 모션 감소 사용자 모두 지원

---

## 3. 브랜드 키워드

- **주**: 신뢰감, 명확함, 효율성, 현대성
- **부**: 따뜻함, 정중함, 투명성
- **톤**: Professional + Approachable (친근하지만 신뢰할 수 있는)
- **회피**: 장난스러움, 복잡함, 과도한 화려함

---

## 4. 핵심 화면 3개의 목적

### Screen 1: 메인 페이지 (`/`)

**목적**: 비회원 전환 및 로그인 사용자 진입점

**주요 섹션**:

1. **Hero**: 서비스 소개 + 회원가입 CTA
   - 주제: "신뢰할 수 있는 답변, 빠른 응답"
   - 비회원: 회원가입 버튼
   - 로그인 사용자: "내 질문 보기" 버튼
2. **이용 흐름**: 3단계 시각화
   - 질문 작성 → 관리자 확인 → 답변 확인
3. **푸터**: 로그인, 서비스 설명

**측정**: 비회원이 1분 내 이용 흐름 이해 (SC-001)

---

### Screen 2: 질문 리스트 페이지 (`/questions`)

**목적**: 질문 목록 조회 및 상태 추적 (회원 보기 vs 관리자 보기)

**회원 보기**:

- 자신의 질문만 표시 (시간 역순)
- 각 항목: 제목 + 작성일 + 상태 배지(대기/답변됨)
- 상단: "질문 작성" 버튼
- 빈 목록: "작성한 질문이 없습니다" 메시지

**관리자 보기**:

- 모든 질문 표시 (시간 역순)
- 각 항목: 제목 + 작성자 + 작성일 + 상태 배지
- 상단: 조회 권한/역할 표시 (관리자)
- 빈 목록: "질문이 없습니다"

**측정**: 관리자가 2분 내 미답변 질문 찾아 상세 페이지 진입 가능

---

### Screen 3: 질문 상세 페이지 (`/questions/:id`)

**목적**: 질문 조회 + 답변 확인/작성

**회원 보기 (답변 대기 중)**:

- 제목 + 내용 (상단)
- 상태: "답변 대기 중" 배지
- 버튼: [수정] [삭제]
- 작성일 메타데이터

**회원 보기 (답변됨)**:

- 제목 + 내용
- 상태: "답변됨" 배지
- 답변 섹션: 답변 내용 + 작성자(관리자) + 작성일
- 버튼: 없음 (수정/삭제 불가)

**관리자 보기 (답변 대기 중)**:

- 제목 + 내용 (상단)
- 작성자 이름 명시
- 상태: "답변 대기 중"
- 버튼: [답변 작성]
- 답변 입력 폼 (텍스트 에어리어)

**관리자 보기 (답변됨)**:

- 제목 + 내용
- 답변 섹션: 자신이 작성한 답변
- 버튼: [답변 수정]

**측정**: 질문 로드 후 1초 내 답변 상태 명확히 인식 가능

## 5. 화면별 정보 우선순위

### 메인 페이지

1. **핵심**: 이용 흐름 (3단계 다이어그램)
2. **차선**: 회원가입 CTA
3. **부가**: 서비스 설명 문구

### 질문 리스트

1. **핵심**: 질문 제목 + 상태 배지
2. **차선**: 작성일 (회원) / 작성자 (관리자)
3. **부가**: 질문 미리보기 (생략 가능)

### 질문 상세

1. **핵심**: 질문 제목 + 본문
2. **차선**: 답변 내용 (있을 경우)
3. **부가**: 메타데이터 (작성자, 작성일, 상태)

  - [수정]

--- 답변 입력 폼 (답변 대기 중이고 관리자인 경우) ---
- Label: "답변"

  - [저장] (주)
  - [취소] (부)

## 8. 회원과 관리자 상태 차이

| 요소           | 회원                | 관리자                      |
| -------------- | ------------------- | --------------------------- |
| 질문 리스트    | 자신의 질문만       | 모든 질문                   |
| 작성자 표시    | 표시 안 함          | 표시 함 (자신 제외 가능)    |
| 수정 버튼      | 답변 대기 중일 때만 | 자신의 답변만               |
| 삭제 버튼      | 답변 대기 중일 때만 | 표시 안 함                  |
| 답변 보기      | 답변됨 상태면 보기  | 모든 답변 보기              |
| 답변 작성      | 불가                | 가능 (미답변 질문)          |
| 상태 배지 색상 | 일반 회원 색상      | 관리자 전용 색상 (선택사항) |

## 9. 페이지 간 이동 구조

```
메인 (/)
  ├─ 회원가입 클릭 → 회원가입 페이지 (명세 범위 외, 디자인 대상 아님)
  ├─ 로그인 클릭 → 로그인 페이지 (명세 범위 외, 디자인 대상 아님)
  ├─ "내 질문 보기" 클릭 (로그인 회원) → 질문 리스트
  └─ 비회원 진입 → 메인에서만 탐색 (보호된 페이지 접근 시 로그인 페이지로 리다이렉트)

질문 리스트 (/questions)
  ├─ 항목 클릭 → 질문 상세 (/questions/:id)
  ├─ "+ 질문 작성" 클릭 → 질문 작성 폼 (상세 페이지와 같은 폼, 작성 모드)
  ├─ 메인 로고 클릭 → 메인
  └─ 로그아웃 클릭 → 메인 (세션 삭제 후)

질문 상세 (/questions/:id)
  ├─ "수정" 클릭 → 질문 수정 폼 (상세 페이지의 같은 폼, 수정 모드)
  ├─ "답변 작성" 클릭 → 답변 입력 폼 (상세 페이지 내 펼침, 관리자만)
  ├─ "답변 수정" 클릭 → 답변 수정 폼 (상세 페이지 내 펼침, 관리자만)
  ├─ Back 버튼 클릭 → 질문 리스트
  └─ 로그아웃 클릭 → 메인
```

### Secondary Palette (내부 페이지)

- **배경**: 밝은 화이트 또는 밝은 그레이 (#F9FAFB)

- **텍스트**: 어두운 네이비 (#0F172A)
- **보조 텍스트**: 그레이 (#6B7280)
- **액센트**: 블루 (#0EA5E9)

### Status Colors

- **답변 대기**: 노란색 또는 주황색 (#F59E0B)

- **오류**: 빨간색 (#EF4444)

### Interaction States

- **호버**: 10% 어두워짐 또는 opacity 감소
- **활성**: 색상 강화 + 언더라인 또는 배경색
- **비활성**: 그레이 (#D1D5DB) + cursor: not-allowed

## 12. 타이포그래피 방향

### Font Selection

- **Font Family**: 현대적이고 가독성 높은 산세리프
  - 추천: Inter, SF Pro Display, Segoe UI, 또는 한국어 시스템 폰트 (Noto Sans KR, SUIT)
- **웹 폰트**: 성능을 고려해 최소 2개 폰트 (본문 + 헤딩) 추천

### Type Scale

- **H1 (메인 헤딩)**:
  - 데스크톱: 48px, font-weight: 700
  - 모바일: 32px, font-weight: 700
  - 예: 메인 페이지 "신뢰할 수 있는 답변, 빠른 응답"

- **H2 (섹션 제목)**:

  - 위아래 부드러운 움직임 (3-5초 사이클)

- **불릿 점**: 깜빡임 없음 (epilepsy 고려)
- **자동 재생 금지**: 사용자 상호작용 필요

## 18. 접근성과 모션 감소 기준

### WCAG 2.1 AA Compliance

- **색상 대비**: 최소 4.5:1 (본문), 3:1 (큰 텍스트)
- **포커스 표시**: 명확한 outline (기본 > custom > 없음 금지)
- **버튼 크기**: 최소 44×44px
- **링크 밑줄**: 색상만으로 구분 금지 (텍스트 또는 밑줄 필수)
- **폼 라벨**: 모든 입력 필드에 라벨 (숨겨진 라벨도 가능)
- **에러 메시지**: 색상 + 텍스트

### Motion Preferences

**prefers-reduced-motion: reduce**

- **애니메이션 제거 목록**:
  - 메인 페이지 오로라 그라데이션 애니메이션
  - 플로팅 카드 애니메이션
  - 스켈레톤 로딩 애니메이션
  - 상태 변경 전환 애니메이션 (토스트 fade 제외)

- **애니메이션 유지 (필수)**:
  - 페이지 전환 (하지만 빠르게)
  - 토스트 fade-in/out (0.2초 이내)
  - hover 상태 변경 (즉시 또는 0.1초 이내)

**테스트**:

```
macOS: System Preferences > Accessibility > Display > Reduce motion
Windows: Settings > Ease of Access > Display > Show animations
Android: Settings > Developer options > Animation scale (0)
iOS: Settings > Accessibility > Motion > Reduce Motion
```

### Keyboard Navigation

- **Tab 순서**: 논리적 (좌→우, 위→아래)
- **Enter**: 버튼 활성화
- **Escape**: 모달/메뉴 닫기
- **초점 관리**: 모달 열 때 첫 입력 필드로, 닫을 때 트리거 버튼으로

### Screen Reader Support

- **Semantic HTML**: button, input, label, form, section 등
- **ARIA Labels**: 필요시 (예: 숨겨진 라벨, 아이콘 버튼)
- **이미지 Alt Text**: 모든 의미있는 이미지에 필수
- **상태 표현**: aria-disabled, aria-current, aria-label 등

## 19. 만들지 말아야 할 디자인

### Anti-Patterns

❌ **과도한 Glassmorphism**

- 배경 투명성 + blur로 정보 숨김
- 텍스트 가독성 저하

❌ **과도하게 둥근 모서리**

- border-radius 24px 이상 사용
- 과도한 귀여움 톤 (신뢰감 훼손)

❌ **흔한 AI/SaaS 랜딩 페이지 패턴**

- 보라색 배경 + 그라데이션 + 추상 3D 모양
- 복사된 느낌의 레이아웃 (슬라이더, 카드 정렬)
- 과장된 카피 ("마법 같은", "혁신적인" 등)

❌ **색상만으로 상태 구분**

- 배지/아이콘 없는 색상 신호
- 예: 파란 카드 = 대기, 초록 카드 = 답변 (텍스트 없음)

❌ **모션 오버로드**

- 동시에 여러 애니메이션 재생
- 페이드인/아웃 + 회전 + 슬라이드 함께 사용
- 무한 반복 애니메이션 (눈 피로)

❌ **모바일 무시**

- 데스크톱 설계를 모바일에 강제
- 터치 대상 30px 미만
- 텍스트 14px 미만

❌ **폰트 오버로드**

- 3개 이상 폰트 혼합
- 고체 또는 극단적 가중치 차이

❌ **정보 밀집**

- padding/margin 부족
- 여백 없이 카드 연결
- 읽기 힘든 라인 높이

❌ **일관성 없는 스타일**

- 버튼 크기/색상/모양 제각각
- 입력 필드 스타일 다양화
- 간격 규칙 불명확

## 20. Claude Design 시안 평가 기준

### Must-Have (필수)

- [ ] 메인 페이지에서 비회원이 1분 내 이용 흐름 이해 가능
- [ ] 회원과 관리자 보기가 명확하게 구분됨
- [ ] 모든 핵심 기능(작성, 조회, 답변)이 명확한 CTA로 표시됨
- [ ] 질문 상태(대기/답변) 배지가 명확함 (색상 + 텍스트)
- [ ] 모바일에서 44px 이상 터치 대상
- [ ] 색상 대비 4.5:1 이상 (WCAG AA)
- [ ] 포커스 표시 명확함
- [ ] prefers-reduced-motion 적용 (애니메이션 제거)

### Should-Have (권장)

- [ ] 메인 페이지 오로라 그라데이션이 미세하고 자연스러움
- [ ] 내부 페이지 가독성이 우수함 (여백, 라인 높이)
- [ ] 버튼 호버 상태가 명확하고 반응적임
- [ ] 로딩/빈 상태가 사려깊게 디자인됨
- [ ] 토스트 메시지가 명확하고 비침투적임
- [ ] 타이포그래피 스케일이 일관성 있음
- [ ] 간격 규칙이 4px 단위로 정렬됨

### Nice-to-Have (추가)

- [ ] 메인 페이지 플로팅 카드가 세련됨
- [ ] 마이크로 인터랙션(호버, 포커스)이 부드럽고 일관됨
- [ ] 다크 모드 고려 (선택사항, 명세 범위 아님)
- [ ] 아이콘 세트가 통일되고 현대적임
- [ ] 에러/경고 상태의 시각적 계층이 명확함

### Rejection Criteria (거절 사유)

❌ 회원 vs 관리자 보기 구분 불명확
❌ 상태 배지가 색상만으로 표시 (텍스트 없음)
❌ 메인 페이지가 흔한 AI 랜딩 페이지처럼 보임
❌ 모바일 레이아웃이 깨짐 (375px에서 테스트)
❌ Glassmorphism 과다 사용 (글자 읽기 힘듦)
❌ 색상 대비가 3:1 미만
❌ prefers-reduced-motion 무시 (애니메이션 여전히 재생)
❌ 버튼 크기 44px 미만
❌ 포커스 표시 없음

1. **Wireframe** (구조): 레이아웃, 정보 우선순위, CTA 배치
2. **Color & Typography**: 색상 팔레트, 폰트 스케일 결정
3. **Component Design**: 버튼, 카드, 배지, 입력장 세부 규칙
4. **Page Design**: 메인, 리스트, 상세 페이지 완성 (회원 + 관리자 뷰)
5. **Interaction Design**: 호버, 포커스, 상태 변경 애니메이션
6. **Accessibility Review**: 대비, 포커스 표시, 키보드 네비게이션 검증
7. **Mobile Check**: 375px, 768px, 1200px 브레이크포인트 확인
8. **Motion Check**: prefers-reduced-motion 활성화 후 테스트
